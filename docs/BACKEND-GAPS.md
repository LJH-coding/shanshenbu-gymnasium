# 後端缺口與可運行替代方案

## 判定

原站不是純前端。單機遊戲主要在瀏覽器執行，但公開 JavaScript 明確呼叫同網域 API 與 WebSocket。公開頁面無法還原 Worker 程式碼、資料表結構、房間狀態、配對演算法、Google OAuth 設定、Cloudflare TURN 金鑰或既有使用者資料。

## 公開程式可觀察到的伺服器介面

| 介面 | 公開程式中的用途 | 靜態版行為 |
| --- | --- | --- |
| `WebSocket /ws` | 1 對 1 房間、觀戰與連線協調 | 不提供；房間按鈕顯示說明 |
| `WebSocket /co` | 四人合作房間 | 本地玩法保留；網路邀請不提供 |
| `WebSocket /mm` | 排位配對與選招流程 | 不提供；配對按鈕顯示說明 |
| `GET /api/ice` | 取得 STUN/TURN `iceServers` | 回傳空清單，不臆造 TURN 憑證 |
| `GET /api/live` | 觀戰中的公開對戰清單 | 回傳空清單 |
| `GET/POST /api/ladder` | 天梯前 100 名與成績提交 | 顯示本機空榜；單機挑戰仍可玩 |
| `GET/POST /api/rogue` | 闖關排行榜與成績提交 | 顯示本機空榜；闖關仍可玩 |
| `GET/POST /api/profile` | 存檔碼備份與跨裝置找回 | 保留 `localStorage`，新增 JSON 匯出／匯入 |
| `GET/POST /api/google` | Google Client ID、帳號綁定與找回 | 回傳未設定，介面顯示尚未開放 |
| `POST /api/t` | 使用統計／遙測 | 靜態版在本機丟棄，不傳送 |

原始碼註解提到排行榜存在 D1；這只能證明前端預期有 D1 服務，無法從公開頁面判定完整 schema 或資料內容。沒有發現可從公開頁面直接還原的 KV 綁定資訊。

## 已做的靜態替代

1. 單機、本地雙人、練習與闖關程式繼續在瀏覽器執行。
2. 個人進度留在 `localStorage`。
3. 選單新增 JSON 進度備份與匯入，使用者可自行保存與搬移。
4. 排行榜 API 以空榜回應，避免整個模式因 404 中斷。
5. 伺服器專用按鈕會說明缺少後端，不會假裝已成功建立房間或配對。
6. 統計端點在本機吞掉，不把資料送到未知位置。

## 若之後要真正重建後端

建議建立獨立的 `server/` 專案，重新定義並文件化 API，不要假設原站內部實作。最低需求包括：

- WebSocket 房間服務與訊息格式驗證
- 排位配對、斷線與重連規則
- WebRTC signaling 與自行管理的 TURN 憑證
- 使用者／裝置識別、濫用防護與速率限制
- 排行榜及存檔資料表 schema、遷移與備份
- OAuth callback、Client ID、Secret 與資料刪除流程
- 清楚的隱私政策與遙測同意

前端目前仍保留原本的介面呼叫位置，因此未來可逐一把 `static-mode.js` 的本機回應換成正式 API base URL。
